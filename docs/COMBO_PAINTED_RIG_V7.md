# 精细原画合击动态 v7（网页版 v4.6）

> 历史版本记录：下文描述 v7 当时的“飞行原画随弹道前进”动作方式与验收。当前 v4.7 已改为召唤物留场、由真实器官发出独立攻击，详见 [v8 留场召唤与独立出招](COMBO_CHOREOGRAPHY_V8.md)。原图来源、哈希和 v7 历史录像保留；当前录制脚本的输出版本以 v8 文档为准。

日期：2026-09-05。用户明确选回凤凰、水龙、圣垒和生命树的精细六阶段原图，要求原图真正运动。本轮不重新生成主体图片、不再用程序几何替代原画；仅作用于 HTML5 可玩版本，未同步 Unity，未修改六套配方、消费、数值与存档。

## 实现方式

- 四张用户原件无修改复制到项目；另外两招复用同一系列的蚀月、军势原画。仍使用当前同一片战场、完整人物和脚下状态，不恢复头像卡框或流程标签。
- 每张原画为 1536×1024、3列2行、六个512×512阶段。运行时只取对应单格：聚能0、成型1、飞行2、命中3、余波4、收束5。阶段间短暂交叠，单格内部持续形变，不是六张静图轮播。
- 新模块 `playable/spirit-codex-combo-art-rig.js` 把实际原画绑定到三角网格，各局部采用不同铰接/位移。成型桌面12×12、手机10×10；飞行/命中8×8、收尾7×7，兼顾多目标开销。网格继承舞台DPR、实际弹道旋转和HUD裁剪，并处理边界防缝、反折与画布状态恢复。
- 原图的 RGB 黑背景通过运行时 SVG 亮度覆盖转换为透明；RGBA 原图保留原透明度。蚀月另去除它原有的方形暗底，只恢复内圆的原画暗月纹理。单格仅缓存一次，不逐帧抠图、不读玩家图像像素；源PNG字节没有改写，支持直接 file 协议打开游戏。
- 人物仍使用按角色ID匹配的48幅动作姿态；武器/掌心 → 融合点 → 合法目标共享真实几何。飞行原画以前缘追随弹头，避免大图中心正确但鼻尖已穿过目标。治疗与召唤仍落在受益者脚下；攻击与护盾对准各自目标。
- 保留独立流光、火花、水滴、地面受光、命中反应与持续余波。主要实体来自原画，这些程序粒子仅作衔接和环境反馈。

## 试玩步骤

1. **Ctrl + F5** 刷新游戏，进入 **城镇 → 编队 → 合击图鉴 → 预览绝招 · 免费 → 完整演出**。
2. 先看炎羽天陨：第1.4–3.2秒应是用户选的精细凤凰，观察翼尖与胸部的相对位置、尾羽摆动；3.2秒起换为侧身飞行原画，仍沿真实弹道运动。
3. 再看雷海龙裁、熔日圣垒、星泉复苏。确认鳞片/建筑细节/树冠保留，并分别观察龙头与龙身、盾片与中央核心、树冠与莲座是否不同步运动。不是整图一起平移。
4. 看命中、HP/盾/治疗/复苏反馈与第7秒余波。暗月应保留暗色月球，但外侧没有方形黑底；其它图也不能出现不透明背景方块或整张六格图。
5. 手机可手动滑动停止跟随，试重播、查看结果、减少动态、关闭/Esc；中文和按钮应完整可用，减少动态不画网格特效。
6. 回补给页确认免费演练库存不变；真实消费测试沿用 [合击配方与操作](COMBO_ULTIMATES.md#再检查真实战斗)。

## 可复现验证

串行运行浏览器验证，避免截图/录制与测试争抢资源。启动 `node tests/playable/server.js`，测试和录制均使用独立非持久浏览器上下文，不接触玩家个人存档。

- 规则：`npx playwright test tests/playable/spirit-codex-combos.spec.js tests/playable/spirit-codex-preparation.spec.js --workers=2`
- 动作与原画动态：`npx playwright test tests/playable/spirit-codex-combo-actions.spec.js tests/playable/spirit-codex-combo-motion.spec.js --workers=2`
- 资产：`spirit-codex.spec.js` 的原图/必需资源用例（47张与六来源哈希）。
- 静帧：`node tests/playable/combo-motion-visual-qa.cjs --file --formation-only`；可加 `--only=phoenix --viewport=compact`。输出系统临时目录 `spirit-codex-painted-rig-v7-qa`。
- 实录：`node tests/playable/ultimate-video-capture.cjs`，输出六段 `ultimate-{id}-v7.webm`；`node tests/playable/ultimate-video-playback-check.cjs` 做只读播放检查。视频为游戏实时画面记录，不作为游戏战斗播放器。

### 本轮验证结果

- **144 个不同定向案例全部通过**：最终原画/动作/资源60/60（3.0分钟）＋随后合击规则/布阵84/84（2.1分钟）。同组专项4/4复测不重复累计，不采用v6历史通过数，不声称重跑历史全量。
- 原画验收逐个检查六来源SHA256、1536×1024尺寸与47张必需图片。实际拦截Canvas裁格、三角clip、纹理采样及UV→屏幕矩阵，验证每次只消费单格原画、同帧大量真实三角采样，而非仅检查调试标记。
- 内部运动检验只使用实际有颜色/alpha的原画区域，拟合全图平移/旋转/缩放/剪切后，剩余局部仍有实质不同位移；全图仿射负控不能通过。防止只动空白网格、或把同一张静图分成许多一起移动的小块冒充内部运动。
- 保留黑底保护：暗像素须能通过实际已绘三角UV回溯到原画暗纹，单格外围另限制黑色占据；源图范围外黑像素负控必须失败。原“任何暗像素都禁止”会误删凤凰暗羽纹与暗月，因此改为有来源依据的纹理/背景区分。实际发现蚀月RGBA原图的方形暗底后已修复，未把该问题当成合法原纹放行。
- 四视口继续通过中文/HUD保护、局部受光、48人物姿态、反向主导身份、真实起终点、手机跟随/手动滑动、4.7秒首命中及110ms错峰、8.4秒生命周期、1.8秒减少动态、免费零副作用和道具原子消费。
- 纯网格辅助验证6,120组主题/密度/时间/组装参数，无反折或退化；确定性、禁用游戏随机流、父画布状态恢复及异常恢复检查通过。此项不等同浏览器帧率承诺，也不并入144项游戏测试。
- 主代理逐组查看桌面/360px精细原画成型截图，file协议六招四形成时点无页面错误和横向溢出；修复后的暗月另做桌面/手机复看，保留月面暗纹且无方形底板。
- 最终六段 v7 录像播放检查 **6/6通过**：均可解码、播放时间推进、时长8.4秒，零媒体/页面错误；录制另核验完整演出各阶段与结束画面。视频检查不计入144项游戏案例。
- 最终 `file://` 模式下，凤凰完整免费预览与真实施放在桌面/360px均通过：无页面错误或横向溢出；实际敌方HP从10000分别变为9590、9590、9569，道具按规则消耗一件。检查使用独立临时浏览器上下文，未触碰用户存档。
