# 合击成型强化 v6（网页版 v4.5）

> 本文保留 v6 程序材质实现与该轮验证历史。用户随后指定保留精细原画并让图内部分运动，当前版本见 [v7 精细原画合击动态](COMBO_PAINTED_RIG_V7.md)。

日期：2026-09-05。范围仅为网页版六种合击的动态呈现，不改角色搭配、数值、消费、次数或存档格式。沿用 v5 同一战场、完整人物和实时材质方案，不恢复巨型插画平面。本轮没有新增生成图片；通过 Canvas 材质运动和局部环境受光增强现有美术。

## 设计与实现

重点是让玩家看见“合击形成”的过程，而不仅是淡入一个完整图形：双源吸入 → 元素分层凝聚 → 核心压缩 → 成型能量向外展开 → 沿真实目标路线释放。保持原来的 8.4 秒完整演出，不靠延长等待制造绝招感。

- 施法者仍使用逐姿态的武器/手掌锚点，融合点在双人与目标之间；释放后固定起点，不随收势拖移。
- 扩大成型主体的有效范围。桌面按舞台宽高限制，最大半径 138px；手机最大 104px，独立留出 220px 成型区。主要轮廓在有效范围内，少量外围细粒只作空间衬托。
- 手机先展示双人，约 1.9–3 秒平缓调整构图使成型主体入镜，3.45 秒后顺接目标方向。手动滑动仍关闭自动跟随，重播恢复。
- 融合点下方增加随蓄力增强的局部地面反射，人物随之轻微受光；不是全屏闪光，不加入持续抖屏或频闪。
- 姓名、HP、护盾与反馈的 Canvas 裁剪保护保留。减少动态仍直接显示静态结果约 1.8 秒，实时法效与地面反光关闭。
- 特效由独立的 `playable/spirit-codex-combo-stage-vfx.js` 绘制；使用程序化路径、渐变及原有少量微粒笔刷，不新增图像解码负担。41 张必需图片不变。

### 六组的成型差异

| 合击 | 成型动作与材质 |
| --- | --- |
| 炎羽天陨 | 双层火羽分批归位，胸颈中轴、喙与尾流组成焰鸟；羽片错相摆动，热核与顺流亮纹强化燃烧感 |
| 雷海龙裁 | 水流沿连续 S 形龙脊汇聚，前后水带、鳍与角凝出形体，流动反射中穿插雷丝 |
| 熔日圣垒 | 熔金护甲片沿弧线装配，侧厚、盾冠与曲面外壳叠合，熔缝热光逐渐稳定 |
| 星泉复苏 | 三束生命茎流向上生长，三层内外莲瓣由收拢转为盛开，叶片与内瓣反射持续流动 |
| 蚀月雷刃 | 两侧弧光与碎片逐段归入刀背，锻成有厚度的交错双刃；外围残片继续旋行 |
| 冥风军势 | 两侧魂流从地面升起并合拱，三层纵深魂影穿出开放魂门，随后分往攻击与召唤目标 |

上述主体均为每帧构建的材质与独立运动，不是图片底板。成型后约 2.7 秒核心开始压缩，约 2.76–3.48 秒仅一次柔和的能量扩散衔接释放；微粒与主材质各有前后层次。

## 如何试玩

1. 打开游戏后按 **Ctrl + F5**，进入 **城镇 → 编队 → 合击图鉴**。
2. 优先选择 **熔日圣垒 → 预览绝招 · 免费 → 完整演出**。重点看第 1.4–3.2 秒：材料应逐层聚成形，再接上正式释放，不是突然贴出一张盾图。
3. 依次预览另外五组。检查轮廓、流动与成型动作是否各有区别；第 7 秒仍应有命中余波。预览不要求拥有角色、能量或催化物，也不会消费。
4. 缩到手机宽度，观察双人 → 成型 → 目标的连续构图；手动滑动后镜头不应抢回。姓名、HP、盾值和关闭按钮应保持清楚可用。
5. 点 **重播 / 查看结果 / 减少动态 / 关闭**，再回补给工坊确认库存未变。减少动态应无成型动画与地面反光。
6. 真实消费按 [合击配方与操作](COMBO_ULTIMATES.md#再检查真实战斗) 测试。规则不变：确认时只消费一次；可见首目标血条在 4.7 秒到达后开始变化，后续目标错开 110ms；跳过或播完均只续战一次。

## 复现与验收

使用独立测试上下文，不操作玩家浏览器存档。测试服务：`node tests/playable/server.js`。

- 四视口规则/准备：`npx playwright test tests/playable/spirit-codex-combos.spec.js tests/playable/spirit-codex-preparation.spec.js --workers=2`
- 四视口动作/材质：`npx playwright test tests/playable/spirit-codex-combo-actions.spec.js tests/playable/spirit-codex-combo-motion.spec.js --workers=2`
- 真实静帧：`node tests/playable/combo-motion-visual-qa.cjs`，支持 `--file`、`--only=bastion`；输出系统临时目录 `spirit-codex-resonance-v6-qa`，新增 2.85 秒与 3.1 秒成型采样。快速复核手机成型可加 `--formation-only --viewport=compact`（四个成型时点，跳过真实施放）。
- 实录：`node tests/playable/ultimate-video-capture.cjs`，录制实际 8.4 秒播放，不使用加速时钟；输出 `ultimate-{id}-v6.webm`，保留旧 v5 视频。不是 AI 视频模型生成，也不是游戏播放一段预渲染录像。
- 视频播放校验：`node tests/playable/ultimate-video-playback-check.cjs`。

### 本轮游戏验证结果

- 四视口 **144 项不同定向案例全部通过**：本轮规则/准备 84/84（2.6 分钟）＋最终材质/动作/生命周期/素材 60/60（3.7 分钟）。未把单独形成专项、结构组或历史 v5 的 140 项重复累计；不是重跑历史全部测试。
- 新增形成专项在每个视口检查六招 × 1600/2200/2800/3150ms：真实融合点周围的像素颜色与空间轮廓确实变化、成熟材料有可辨面积且不铺满舞台、六招形态不同、无不透明黑底。不是仅断言 class/data 标记。
- Canvas 仍禁止旧技能整图和覆盖舞台超过 25% 的位图绘制；姓名/HP/盾/反馈的 Canvas 区域透明。新局部地面受光必须跟随实际融合点、面积受限且不拦截点击；减少动态时受光隐藏、Canvas 为空。
- 原 48 姿态、正反主导身份、真实武器起点与目标终点、手机镜像/滚动/缩放、4.7 秒首命中及 110ms 错峰、正确复活/召唤对象继续通过。免费零资源/存档/随机流副作用、自然结束/跳过一次续战和取消隔离保持，41 张必需图解码通过。
- 早期截图与测试并发时，结构组出现 2 个桌面超时（没有布局或数值断言失败）。停止其它浏览器工作后，以相同 2 workers 和原超时完整复测 60/60 通过；没有放宽阈值、跳过用例或以旧结果替代。
- 主代理逐组检查桌面/360px 成型截图，以及最终凤凰、雷海、圣垒、星泉的色光调整。独立静帧流程六组全程及真实凤凰两视口均无页面错误、无横向溢出；本地 file 协议的场景与真实施放也已检查。未操作玩家自己的浏览器存档。
- 六段最终 v6 实录全部录制完成：1280×720、25fps 编码、8.40 秒、无音轨，总计 7,886,051 字节（约 7.89MB）。录制时游戏实际六阶段完整运行、免费预览前后状态相同；另做浏览器播放 **6/6 通过**，0 媒体错误，不计入 144 项游戏案例。
